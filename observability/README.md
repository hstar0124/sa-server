# observability

Prometheus 스크레이프 설정과 Grafana 대시보드가 들어올 자리다. 부하·장애 단계에서 채운다. 그때까지 프로세스는 자체 통계 로그(틱 지연, 세션 수 등)를 남긴다.

## 수집할 지표

| 영역 | 주요 지표 |
|---|---|
| Zone | 틱 처리 시간 p50/p95/p99, 예산(50 ms) 초과 비율, 큐 길이, 객체 수 |
| 네트워크 | 입력→결과 지연, RTT, 세션당 송신량, 전송 큐 적체 |
| AOI | 플레이어당 관심 객체 수, 생성·제거 메시지 수 |
| Backend | 경제 명령 지연, 성공·거절·미확정 비율, 연결 풀 대기 |
| PostgreSQL | 트랜잭션 지연, 잠금 대기, WAL 증가량, 디스크 지연 |
| 이벤트 | 가장 오래된 미발행 Outbox 나이, consumer lag, 재시도·DLQ 수 |
| 호스트 | CPU 스로틀링, 메모리, SSD 여유·지연, 온도 |

틱 간격이 50 ms라고 매 틱 49 ms를 쓰는 상태를 여유 있다고 보지 않는다. 보고할 때는 접속자 수만이 아니라 맵 크기, 밀집도, 몬스터 수, 스킬 빈도, 패킷 크기, 측정 시간, DB 내구성 설정을 함께 적는다.
