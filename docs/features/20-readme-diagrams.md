# 20 README 다이어그램: 지금까지 만든 것을 그림으로

## 배경과 목표
README는 저장소를 처음 연 사람에게 큰 그림을 주는 곳이다. 지금까지는 전체 구조, 틱 흐름, 몬스터 상태 그림만 있었다. 프로세스 안의 구성, 데이터 모델, 세션 상태, 스킬 처리 순서는 글로만 설명했다. 이 PR은 그것들을 그림으로 더한다. 규칙은 같다. README에는 **지금까지 만든 것만** 그린다. 완료 조건: 새 그림이 모두 실제 클래스·테이블·상태 이름과 맞고, 문법 오류 없이 그려진다.

## 고민한 선택지와 결정
| 주제 | 선택지 | 결정 |
|---|---|---|
| 그림을 어디에 | 별도 "다이어그램" 절 / 각 주제 절 안에 | 주제 절 안에. 프로세스 내부는 "전체 구조", 데이터 모델은 "데이터의 기준", 세션 상태는 "네트워크와 입장", 스킬 흐름은 "전투", 실행 구성은 "빌드"에 둔다. 글과 그림이 같은 자리에 있어야 함께 읽힌다 |
| 이전 이력의 그림 | 그대로 / 만든 것만 남기고 고침 | 고친다. 배포 그림의 "6단계부터 K3s" 부분은 아직 만들지 않아 뺐다. 스킬 흐름의 전투 이벤트 수신자는 15에서 고친 실제 동작으로 맞췄다. 틱 흐름과 몬스터 상태는 README에 이미 있어 넣지 않았다 |
| 그림 도구 | 이미지 파일 / mermaid | mermaid. GitHub이 바로 그리고, 텍스트라 PR에서 바뀐 곳이 보인다 |

## 구현
- 전체 구조 › 프로세스 내부: Gateway·Zone·Backend 안의 구성 요소와 호출 방향. I/O를 모르는 순수 코드는 회색으로 구분
- 데이터의 기준: PostgreSQL 테이블 일곱 개와 관계, 정합성을 지키는 제약(조건부 UPDATE, 부분 유일 인덱스, 펜싱 토큰)
- 네트워크와 입장: Gateway 세션 상태 기계(대기 → 소비 → 붙임 → Zone 안 → 닫힘)와 거절 경로
- 전투: `CastSkill`부터 `CommandResult`·`CombatEvent`까지의 순서도
- 빌드: 로컬 실행 구성(compose의 PostgreSQL과 호스트 프로세스, 포트)
- 마이그레이션 0002·0003의 주석에 남은 설계 문서 절 번호 세 개를 지웠다(아래 문제)

## 만난 문제
- 데이터 모델을 그리려고 마이그레이션을 읽다가, SQL 주석에 지워진 설계 문서의 절 번호 세 개가 남아 있는 것을 찾았다. [이슈 007](../issues/007-bare-design-section-numbers-left-in-comments.md)의 검토가 SQL 주석을 훑지 않았기 때문이다. 주석을 고치고, 검토 대상에 SQL·HTML·CSS를 더했다. Migrator는 적용 기록을 스크립트 이름으로만 남기므로 이미 적용된 DB와 어긋나지 않는다. 이슈 007에 이 내용을 덧붙였다.

## 검증
- 그림의 이름이 코드와 같다. 클래스 9개(`ClientSession`, `SessionProtocol`, `EntryTicketVerifier`, `ZoneLink`, `DirectoryClient`, `TickRunner`, `ZoneHost`, `GatewayLinkServer`, `LeaseKeeper`)를 소스에서 찾았다. Backend 모듈 3개, 테이블 7개와 제약, 세션 상태 enum 5개도 확인했다.
- README의 mermaid 블록 8개를 헤드리스 Chromium에서 mermaid 10.9.1로 모두 렌더링했고, 오류가 없었다.
- 참조 검토 스크립트 출력 없음.
