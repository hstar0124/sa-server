# 56 (8c) 링크 세그먼트 상한: 2,000명 입장 중 링크가 멈추던 교착 해결

## 배경과 목표
이 프로젝트의 Gateway와 Zone(둘 다 C++)은 Zone마다 TCP 연결 하나로 이어진다. Gateway→Zone으로는 입력과 하트비트(1초마다)가 간다. Zone→Gateway로는 스냅샷과 결과가 간다. 양쪽 모두 5초 동안 아무것도 오지 않으면 상대를 죽은 것으로 보고 링크를 닫는다(48의 생존 확인). 그러면 그 Zone의 세션이 모두 끊긴다.

8c를 마치며 용량 사다리를 다시 잴 때, 봇 2,000명에서 일곱 번 중 두 번 링크가 침묵 판정으로 끊겼다. 원래 56 자리였던 Gateway 다중 스레드는 측정으로 보류했다(55: 2,000명에서 Gateway 0.40코어). 그 자리에 이 교착을 넣었다.

완료 조건:
- 원인을 측정으로 밝힌다.
- 2,000명 반복 실행에서 끊김이 없다.
- 자동 조정과 CPU를 잃지 않는다.

## 고민한 선택지와 결정
| 주제 | 선택지 | 결정 |
|---|---|---|
| 원인 | 과부하(이슈 020과 같은 것) / 커널 수준 정체 | 커널 수준 정체. 링크 소켓을 0.5초마다 기록하니 프로세스는 한가했다. 송신 측은 큐가 2.6 MB인데 1.6초째 보내지 않았다. 수신 창은 55,296바이트에 묶여 있었고, 이것이 세그먼트 하나(루프백 약 64 KB)보다 작았다([이슈 021](../issues/021-link-stalls-when-a-segment-exceeds-the-window.md)) |
| 해결 | 소켓 버퍼 명시(이전 이력) / 침묵 기한 늘리기 / 세그먼트 줄이기 | 세그먼트 줄이기. Zone의 수신 대기 소켓에 `TCP_MAXSEG` 16 KiB를 건다. 버퍼 명시는 52에서 재 보고 뺐다(커널 상한 208 KB에 잘리고 자동 조정이 꺼짐). 기한을 늘려도 창 탐색 간격은 계속 두 배가 되어 언젠가 넘는다 |
| 어느 쪽에 거나 | 양쪽 / Zone의 수신 대기 소켓만 | Zone만. MSS는 연결할 때 양쪽이 광고한 값 중 작은 쪽이라, 한쪽에서 걸어도 두 방향이 모두 16 KiB가 된다. Gateway는 asio의 범위 connect가 소켓을 내부에서 다시 열어 옵션을 걸 자리가 마땅치 않기도 하다 |

## 측정 (봇 2,000명, release)
| | 수정 전 | 수정 뒤 |
|---|---|---|
| 끊긴 실행 | 7번 중 2번 | **6번 중 0번** |
| 링크 MSS | 약 64 KB | 16,372 B |
| Zone / Gateway CPU | 0.50 / 0.40 | 0.50 / 0.39 |
| 놓친 틱 / 미룬 스냅샷 | 0 / 0 (끊긴 실행은 9.3만 미룸) | 0 / 0 |

## 구현
- Zone 설정 `gateway_link.max_segment_bytes`(16 KiB). 0은 거부한다. 커널이 받지 않는 값이면 시작할 때 실패한다.
- `GatewayLinkServerConfig::max_segment_bytes`. `GatewayLinkServer`가 수신 대기 소켓에 `TCP_MAXSEG`를 건다(asio에 이식성 있는 이름이 없어 `asio::detail::socket_option::integer`로 정의).
- compose의 zone-a·zone-b 설정에 값과 이유를 적었다. K3s는 같은 파일을 쓴다.
- `scripts/bench/capacity.sh`: 봇 수가 Gateway 연결 상한을 넘으면 그 실행에서만 환경 변수로 올린다(55에서 넣음).

## 지킨 것 (이번 저장소의 개선)
- 48의 생존 확인과 침묵 기한(5초)은 그대로다. 기한은 죽은 상대를 찾는 장치이고, 이번 문제는 기한이 아니라 링크가 실제로 멈춘 것이었다.
- 52에서 측정으로 뺀 소켓 버퍼 명시를 되살리지 않았다. 자동 조정이 그대로 버퍼를 키운다.
- 50의 묶음 쓰기와 51의 예산은 그대로다. 링크 대기는 1.2~1.5 MiB에 머문다.

## 만난 문제
- [이슈 021](../issues/021-link-stalls-when-a-segment-exceeds-the-window.md): 수신 창이 세그먼트 하나보다 작아 링크가 5초 넘게 멈춤

## 검증
- C++: 테스트 309개 통과. 설정 검사가 세그먼트 상한 0을 거부한다.
- dev·release·ASan, clang-tidy, clang-format 통과.
- 2,000명 여섯 번 통과. 소켓 기록에서 링크 MSS 16,372를 확인했다.
- 로컬 end-to-end(smoke·fighters·looters·travelers): 통과.

## 남긴 것
- 클라이언트 연결(Gateway→봇)도 루프백이면 같은 구조가 될 수 있다. 다만 클라이언트로 가는 양은 스냅샷 하나(약 300 B)씩이라 세그먼트를 채우지 않는다. 느린 클라이언트는 52의 송신 한도가 끊는다.
- Gateway 다중 스레드: 보류(55의 측정).
