# 09 설계 문서를 README로 흡수: 현재 방향과 맞는 것만 남기고 원문 제거

## 배경과 목표
02에서 넣은 설계 문서(`docs/Server_Architecture.md`, v1.0)는 구현 전 가정이 섞여 있다. 1단계 K3s, 장비 파티션 계획, Redis 티켓·presence, 메모리 예산 같은 것들이 이미 ADR로 뒤집혔거나 뒤집힐 예정이라, 읽는 사람이 문서와 ADR을 매번 대조해야 현재 방향을 알 수 있다. README가 "구성, 흐름, 선택 이유, 측정 요지"를 한눈에 주는 자리이니, 현재 구현 방향과 일치하는 내용만 README로 옮기고 원문은 저장소에서 뺀다. 완료 조건: 원문 제거, 코드·문서의 "설계 문서 N절" 참조가 남지 않고 모두 실제로 존재하는 자리를 가리킨다.

## 고민한 선택지와 결정
| 선택지 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 원문 유지, ADR로 차이만 기록 | 변경 최소 | 무엇이 현재 방향인지 두 문서를 대조해야 함 | 기각 |
| 원문 제거, 참조도 지움 | 단순 | "왜"의 맥락이 코드에서 사라짐 | 기각 |
| **맞는 내용만 README·전용 문서로 옮기고 참조를 그 자리로** | 한 곳에서 현재 방향을 읽음, 참조가 살아 있음 | 참조 수십 개 수정 | 채택 |
| 이력에서도 원문 삭제(force push) | 흔적이 없음 | 병합된 PR 8개의 커밋 링크가 깨짐 | 기각. 앞으로만 뺀다 |

## 검증
- 남은 참조 검사: `git grep -iE 'Server_Architecture|설계 문서 [0-9]|design document'`가 ADR-0001의 기록과 피처 문서(02)만 돌려준다. 남은 README 참조("네트워크와 입장", "Zone의 한 틱", "소유권과 lease", "데이터의 기준")가 모두 실제 제목으로 존재한다. 아직 README에 없는 주제를 가리키던 참조는 포인터를 지우고 문장만 남겼다.
- 주석만 바뀌었으므로 C++ 테스트 96개, .NET 빌드, clang-format(재정렬 1곳), `dotnet format` 통과.

리뷰에서 바뀐 것:
- README에는 **그 시점까지 만든 것만** 적는다. 미래 단계의 방향과 아직 하지 않은 측정을 미리 적지 않는다. 각 단계 PR이 자기 내용을 README에 더한다.
- "진행 상태" 표와 "지금까지 증명한 것" 목록은 두지 않는다. 진행 기록은 `docs/features/README.md`(피처 색인)가 맡는다.
- 측정이 생기는 단계부터 README에 "성능과 개선" 절이 생긴다. 부하별 리소스 사용량과, 측정에서 드러난 문제를 *증상 → 원인 → 조치 → 다시 잰 결과*로 적는 개선 사례.
