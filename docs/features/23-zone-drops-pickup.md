# 23 (5단계) Zone 드롭과 획득: 굴리고 예약하고, 확정은 Backend가

## 배경과 목표
22에서 Backend가 처치 보상과 획득을 한 트랜잭션으로 처리하게 됐다. 이 PR은 Zone 쪽을 잇는다. 몬스터가 죽으면 Zone이 드롭을 굴려 Backend에 처치를 기록하고, 커밋된 아이템만 바닥에 보인다. 플레이어가 아이템을 집으면 Zone이 그 아이템을 예약하고 Backend에 정산을 맡긴다. 원칙은 "Zone은 굴리고 예약할 뿐, 자산을 확정하는 것은 Backend"이고, Zone의 틱은 Backend의 답을 기다리지 않는다. 완료 조건: 처치에서 바닥 아이템, 획득, 인벤토리 갱신까지 실제 스택에서 이어지고, Backend가 답하지 않는 경우까지 테스트로 확인한다.

## 고민한 선택지와 결정
| 주제 | 선택지 | 결정 |
|---|---|---|
| 아이템이 바닥에 생기는 시점 | 굴리자마자 / Backend가 커밋한 뒤 | 커밋 뒤. 굴리자마자 보이면 DB에 없는 아이템을 집으려는 요청이 생긴다. 바닥에 보이는 아이템은 모두 DB에 있다 |
| 처치 기록 실패 | 버림 / 다시 보냄 | 다시 보낸다(정해진 횟수). 처치 ID가 같아 재시도해도 보상은 한 번이고, 버리면 플레이어의 보상이 영영 사라진다 |
| 획득 경합 | Backend에만 맡김 / Zone이 먼저 예약 | Zone이 먼저 예약한다. 같은 Zone 안의 경합은 예약에서 걸러 Backend 왕복을 줄인다. 예약된 아이템은 남이 집지 못하고 소멸하지도 않는다. 최종 판정은 여전히 Backend의 조건부 UPDATE다 |
| 클라이언트에 주는 첫 답 | Backend 답까지 침묵 / 대기(`PENDING`) | 대기를 바로 준다. Backend 답이 오면 최종 결과와 인벤토리 전체 상태를 보낸다 |
| 답이 없을 때 | 실패로 간주 / "모름"(`UNKNOWN`) | 모름. 같은 요청 ID의 재시도가 다시 Backend까지 가고, Backend의 요청 결과 테이블이 그 재시도를 안전하게 만든다. Zone은 모름을 기억해 두지 않는다 |
| 16바이트 ID | 프로세스 ID 타입 재사용 / 꼬리표로 구분한 공통 템플릿 | `OpaqueId<Tag>`. 인스턴스 ID, 아이템 인스턴스 ID, 처치 ID가 같은 구현을 쓰되 서로 바꿔 넘길 수 없다 |

## 구현
- `common`: `OpaqueId<Tag>`로 16바이트 ID 일반화. `InstanceId`, `ItemInstanceId`, `KillId`
- `zone/sim`: `zone_items.cpp`(드롭 굴림, 바닥 아이템, 획득 검증·예약·정산 반영, 소멸), 획득 명령과 처치 기록·획득 예약 이벤트, 틱에 바닥 아이템 소멸 단계
- `zone/server`: `EconomyClient`(gRPC, 마감 시간, 처치 기록 재시도), `codec`의 처치·획득·인벤토리 변환, `ZoneHost`의 처치 기록·획득 정산·입장 시 자산 조회, 설정
- clang-tidy: 인지 복잡도 계산에서 매크로를 뺐다. gtest 단언이 분기로 펼쳐져 메시지를 여러 개 다루는 테스트의 점수를 지배했다. 이 설정 커밋을 기능 커밋보다 앞에 두어 커밋마다 정적 분석이 통과하게 했다
- 획득 요청 키 수정(아래 문제 012)
- 테스트 14개: 시뮬레이션 5개, 호스트 6개, 코덱 3개(아래 검증)
- README: 구조 표, 프로세스 내부, 데이터의 기준, 틱 흐름, "자산과 멱등성"에 Zone 쪽 흐름과 처치부터 획득까지의 순서도

## 만난 문제
- [013](../issues/013-redeem-assigns-a-dead-zone-instance-after-restart.md) end-to-end를 연달아 돌리자, 전투 프로필의 처치가 모두 "낡은 소유권"으로 거절됐다. Backend가 직전 실행의 죽은 Zone 인스턴스(lease가 아직 살아 있던)에 캐릭터를 배정했기 때문이다. 이 PR의 기능은 정상이고(lease 만료 뒤 단독 실행에서 처치 11건 모두 기록), 결함은 Backend 배정에 있어 다음 수정 PR에서 고친다. 이전 이력에도 있던 결함이다.
- [012](../issues/012-pickup-request-key-collides-across-sessions.md) 획득 요청 키가 세션을 넘어 겹친다. 이전 이력은 이 결함을 몇 피처 뒤에 따로 고쳤다. 11에서 정한 "같은 파일의 다음 수정 커밋을 확인한다"로 찾았고, 알고 있는 결함을 싣지 않도록 이 PR로 당겨 왔다.
- 옮긴 커밋이 15에서 지운 겹친 테스트를 다시 넣으려 했다. 그 부분은 빼고, 14에서 넣은 테스트는 `ZoneHost` 생성자가 경제 의존성을 받게 바뀐 데 맞춰 고쳤다.
- 자동 치환이 인벤토리·획득 주석 두 곳을 "네트워크와 입장"으로 연결하고 "매번 전체 상태"라는 설명을 지웠다. "자산과 멱등성"을 가리키게 고치고 설명을 되살렸다. 숫자만 남은 `(6.3)`도 지웠다.
