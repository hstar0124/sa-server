# 19 설계 노트 자기완결화: 노트 하나만 읽어도 이해되게

## 배경과 목표
설계 노트는 "왜 이렇게 만들었나"를 설명하는 글이고, 포트폴리오를 보는 사람이 가장 먼저 여는 문서다. 그런데 노트 01~05는 프로젝트 배경 없이 바로 본론으로 들어갔다. 그리고 지워진 설계 문서나 README 절을 근거로 들며 설명을 다른 문서로 넘기는 곳이 남아 있었다. 노트 하나만 링크로 받은 사람은 Gateway·Zone이 무엇인지, 20 Hz·10 Hz가 어디서 나왔는지 모른 채 읽게 된다. 이 PR은 모든 노트를 그 노트만으로 읽히게 하고, 이 원칙을 작업 규칙에 적는다. 완료 조건: 노트 01~06 모두 서두에 배경 절이 있고, 다른 문서의 절 번호로 설명을 떠넘기는 곳이 없다.

## 고민한 선택지와 결정
| 주제 | 선택지 | 결정 |
|---|---|---|
| 배경을 어디에 | 노트 색인에 한 번 / 노트마다 | 노트마다. 노트는 링크 하나로 따로 공유된다. 서두 2~4문장에 프로젝트, 등장하는 구성 요소, 이 글이 답하는 질문을 둔다 |
| 다른 문서의 내용 | 링크로 넘김 / 그 자리에 요지를 다시 적음 | 요지를 다시 적는다. 링크는 "더 읽을 거리"로만 남긴다 |
| 이전 이력의 README 재작성 커밋 | 함께 가져옴 / 가져오지 않음 | 가져오지 않는다. 이 저장소의 README는 "만든 것만" 규칙으로 처음부터 새로 써 왔고, 그 커밋은 진행 상태 절을 담고 있다 |
| 규칙 문장 | 이전 그대로 / 이 저장소의 README 규칙에 맞춤 | 맞춘다. 이전 문장의 "README에 진행 상태"를 빼고, 측정치는 그 단계에서 잰 것만 "성능과 개선"에 적는다고 썼다 |

## 구현
- 노트 01~05: 서두에 "배경" 절. README 절 이름이나 지워진 설계 문서를 근거로 들던 문장을 그 자리의 설명으로 바꿨다
- 노트 06: 16에서 쓴 서두를 배경 절로 옮기고, 이벤트에 담기는 필드를 그 자리에서 설명했다
- 노트 색인: 각 글이 그것만으로 읽힌다는 문장
- CLAUDE.md 작업 방식: 문서 역할(README는 만든 것의 큰 그림, 설계 노트는 자기완결)

## 만난 문제
- 이전 이력의 노트 커밋을 옮기자 노트 다섯 개와 색인이 충돌했다. 이 저장소에서 노트에 따로 바뀐 것이 있었기 때문이다. 12의 WebSocket 반영, README 절 참조, 15·16의 06 수정이다. 이전 판의 배경 절과 자기완결 문장을 바탕으로 이 저장소의 바뀐 사실을 다시 얹었다.
- 노트 01은 이전 판에서 TCP 선택의 근거를 "원 설계"로 들었다. 그 문서는 이 저장소에 없다. 그래서 근거를 현재 사실("초기 개발과 디버깅을 위한 선택이고, 손실 지연을 잰 뒤 UDP로 옮길지 정한다")로 적었다.
- 이전 판의 노트 06은 이벤트 수신자를 "피격자를 보는 모두와 공격자"로 적었다. 15에서 고친 실제 동작(피격자 자신 포함, 공격자만 보이는 플레이어는 제외)과 16에서 다시 잰 수치를 유지했다.

## 검증
- 노트 01~06 모두 `## 배경` 절이 있다.
- 지워진 설계 문서나 다른 문서의 절 번호를 근거로 드는 곳이 없다(참조 검토 스크립트 출력 없음, "원 설계"·"설계 문서" 검색 결과 없음).
- 노트의 상대 링크가 모두 실제 파일을 가리킨다.
- 노트 01의 코드 구조 그림(`TcpByteStream`, `FramedConnection`, `WebSocketConnection`, `MessageConnection`, `SessionProtocol`)이 실제 클래스 이름과 같다.
