# 27 Zone 리뷰 수정: 유한한 입력, 빠짐없는 델타, 상한 있는 큐, 막히지 않는 몬스터

## 배경과 목표
이 저장소는 먼저 만든 이력을 피처 단위로 다시 쌓으면서, 이미 옮긴 0~5단계 코드를 한 번 회고 리뷰했다([2026-10-20 회고 리뷰](../reviews/2026-10-20-retrospective.md)). 이 PR은 그중 Zone 서버 지적 Z1~Z10을 다룬다. Zone은 지역 하나를 20 Hz 틱으로 시뮬레이션하는 C++ 프로세스다. 시뮬레이션 코어(`zone/sim`)는 소켓·시계를 모르는 순수 라이브러리이고, 호스트(`zone/server`)가 Gateway 링크에서 받은 입력을 넣고 10 Hz로 플레이어마다 스냅샷 델타를 보낸다. 높음 2건은 무한대 입력 하나로 위치가 NaN이 되어 맵 어디서나 몬스터를 때리고 아이템을 줍는 것(Z1), 스냅샷 사이의 틱에 일어난 변화와 정지가 전달되지 않아 멈춘 늑대가 화면에서 계속 미끄러지는 것(Z2)이다. 완료 조건: 지적마다 코드로 확인하고 고치며, 고친 경우는 수정 전 코드에서 실패하는 테스트로 고정한다.

## 고민한 선택지와 결정
| 주제 | 선택지 | 결정 |
|---|---|---|
| 유한하지 않은 입력 | 경계(코덱)에서 거절 / 시뮬레이션이 견딤 | 둘 다. 코덱이 버리고 `bad_inputs`로 세어 악용이 지표에 보인다. 시뮬레이션은 정규화가 방향 없는 벡터를 0으로 만들고, 사거리 판정을 NaN이면 거짓이 되는 `WithinDistance` 하나로 모아, 무엇이 새어 들어와도 위치에 NaN이 생기지 않는다 |
| 델타의 기준 | 틱마다 불리언 플래그 / 바뀐 틱 스탬프 | 스탬프. 엔티티는 스냅샷 내용이 마지막으로 바뀐 틱을, 플레이어는 이전 스냅샷의 틱을 남긴다. 스냅샷 주기가 시뮬레이션 주기와 달라도 사이의 변화를 놓치지 않는다. 먼저 만든 이력은 이 문제를 송신 역압 단계에서 같은 방식으로 고쳤다. 정지(속도 변화)를 변화로 치는 것은 이번에 더했다 |
| 이동 입력 쌓기 | 모두 큐에 / 플레이어마다 최신 하나 | 최신 하나. 이동은 변위가 아니라 방향(의도)이라 중간 입력을 건너뛰어도 결과가 같다. 틱당 이동은 플레이어 수로 묶이고 예산이 필요 없다. 처리 확인 번호(`last_processed_input_seq`)는 최신 번호로 건너뛴다 |
| 시전·획득이 넘칠 때 | 조용히 버림 / 새 거절 코드 / 결과 "모름" | "모름"(`UNKNOWN`). 계약에 이미 있는 "처리되지 않았으니 같은 요청 ID로 다시 보내라"는 뜻 그대로다. 계약을 바꾸지 않는다 |
| 막힌 몬스터의 판정 | 목표와의 거리가 줄지 않음 / 몬스터 자신이 움직이지 않음 | 자신의 이동. 거리로 보면 더 빠른 플레이어를 쫓는 정상 추격까지 포기한다. 그 추격은 원래대로 리시 반경이 끝낸다 |
| 막힌 귀환 | 그 자리에서 대기 / 귀환 지점으로 옮김 | 옮김. 경로 탐색이 없으니 기다려도 풀리지 않는다. 화면에서는 한 번 순간 이동한다 |
| 같은 틱 효과의 순서 | 해시 순서(같은 빌드에서는 재현됨) / 엔티티 ID 순서 | ID 순서. 정해진 규칙이 생기고, 먼저 생긴 공격이 처치를 가져간다. 정렬 비용은 틱당 수천 개 수준이다 |
| 몸 반경 | 코드 상수 그대로 / game-data | game-data(`movement.body_radius_m`). 스폰 검증과 이동이 같은 값을 써야 해서 이번에 옮겼다. 나머지 상수(사거리 허용치, 무리 반경)는 규칙 정리 PR |

## 리뷰에서 고친 것
| 지적 | 고친 것 |
|---|---|
| 무한대 이동 입력 하나로 위치가 NaN이 되어 아무에게도 안 보이고, 모든 사거리 비교가 거짓이 되어 맵 어디서나 때리고 줍는다. 그런 방향의 투사체는 끝나지 않는다(Z1) | 코덱이 NaN·무한대 좌표를 거절하고 센다(`InputError::kNonFiniteVector`). `Normalized`는 길이가 0·NaN·무한대이면 0, 투사체는 정규화한 방향이 0이 아니어야 한다. 사거리 판정 다섯 곳을 `WithinDistance`로, 격자는 NaN을 0번 칸으로 |
| 스냅샷 델타가 스냅샷 틱의 변화만 보고, 정지를 변화로 치지 않는다(Z2) | `changed_at`(엔티티)·`viewed_at`(플레이어) 틱 스탬프, 속도가 바뀌면 스탬프 |
| 입력 큐에 상한이 없고, 미룸 통계가 같은 명령을 틱마다 다시 센다(Z4) | 이동은 플레이어마다 최신 하나(`moves_superseded`), 시전·획득은 플레이어당 `input.max_queued_per_player`를 넘으면 "모름"(`commands_dropped`), 미룸은 명령마다 한 번 |
| 벽에 막힌 몬스터가 추격·귀환 상태로 영영 멈춘다(Z5) | `combat.monster_stall_timeout_ms` 동안 `combat.monster_stall_distance_m`를 못 움직이면 추격은 귀환으로, 귀환은 귀환 지점으로 옮김 |
| 스폰 검증이 충돌 모델과 다르다(맵 가장자리 (0,0) 스폰이 통과하고 움직일 수 없다). 무리 귀환 지점은 검사하지 않는다. TOML `nan`이 "0 이하" 검사를 통과해 격자 생성자에서 미정의 동작(Z7) | `MapData::IsWalkable` 하나를 이동과 검증이 함께 쓴다. `Zone::Create`가 스폰 지점과 모든 귀환 지점을 본다. 로더가 NaN·무한대·float 범위 밖 숫자를 거절한다 |
| 같은 틱 두 타격의 처치 귀속과 부활 지점이 해시 순서를 따른다(Z9) | 시전 발동, 투사체, 몬스터 판단, 부활을 엔티티 ID 순서로 |
| 낡은 주석, 551줄 로더, 알 수 없는 클래스를 "호출자 버그"라 부르며 빈 optional을 돌려줌(Z10) | TOML 필드 접근을 `toml_fields`로 분리(로더 410줄), `SpawnPlayer`가 `SpawnError` 반환, 틱 실행기·개발 봇 호스트 주석, clang-format이 둘로 가른 절 제목 |

미룬 것: Gateway 링크 송신 큐 상한(Z3)과 1~2천 명 성능(Z6)은 먼저 만든 이력대로 송신 역압·밀집 처리량 피처에서 한다. 규칙 위반 상수(Z8)는 규칙 정리 PR. 리뷰가 빠진 테스트로 꼽은 `TickRunner` 따라잡기는 규칙이 `FixedStepScheduler`에 있고 그쪽에 테스트가 있다. `TickRunner` 자체를 시험하려면 시계를 주입받게 바꿔야 해서 규칙 정리 PR로 넘겼다.

## 구현
- `common/geometry`: `Vec2::IsFinite`, 방향 없는 벡터에 0을 주는 `Normalized`, `WithinDistance`
- `zone/server/codec`: `InputError`, `ToMoveCommand`·`ToCastCommand`가 `std::expected`를 반환. `ZoneHost::Input`이 거절을 `bad_inputs`로 센다
- `zone/sim`:
  - `Zone`: `changed_at`·`viewed_at`, `SetVelocity`, `ChangedSince`. 입력은 `pending_moves_`(플레이어마다 최신 이동)와 `pending_`(시전·획득, 도착 순서), `queued_per_player_`. 통계 `commands_dropped`, `moves_superseded`
  - 몬스터: `headway_from`·`stall_deadline`, `Stalled`, `ReturnHome`, `SettleAtHome`
  - `IdsInOrder`로 시전 발동·투사체·몬스터·부활을 ID 순서로
  - `MapData::IsWalkable`, `ValidateWalkable`, `HomesOf`(무리 귀환 지점 계산을 맵으로 옮김). `SpatialGrid`의 NaN 처리
  - `SpawnError`
- `zone/data`: `toml_fields.{hpp,cpp}`(필드 읽기, 유한한 숫자만), 로더는 도메인별 해석만
- game-data `rules/movement.toml`: `movement.body_radius_m`, `input.max_queued_per_player`, `combat.monster_stall_timeout_ms`, `combat.monster_stall_distance_m`
- 틱 통계 로그에 `refused`(넘쳐서 "모름"으로 돌려준 요청)와 `superseded`
- README: Zone의 한 틱(입력과 스냅샷), 전투(로드·생성 검증, 막힌 몬스터, 같은 틱 순서), 상태도

## 만난 문제
- 피해 델타 테스트를 처음 썼을 때 수정 전 코드에서도 통과했다. 맞은 슬라임이 다음 틱에 공격자를 향해 움직였고, 이동이 그 틱의 변화로 잡혀 체력이 우연히 함께 실렸다. 공격자를 슬라임의 공격 사거리 안에 세워 슬라임이 움직이지 않게 하자 수정 전 코드에서 실패했다.
- 막힌 귀환 테스트는 플레이어가 슬라임을 벽 뒤로 끌고 가야 한다. 플레이어가 "슬라임이 1.4 m 안에 오면 한 걸음"으로 움직이게 했더니 출발하지 않았다. 슬라임은 공격 사거리(1.5 m)에 들면 멈추는데, 그 거리가 정확히 1.4 m였다. 기준을 공격 사거리로 바꿨다.
- 막힘 판정을 처음에는 "목표에 가까워졌는가"로 생각했다. 그러면 플레이어를 따라가는 슬라임도 거리가 줄지 않아 포기한다. 몬스터 자신의 이동으로 바꿨다.

## 검증
- C++: dev 176 → 195개 통과, clang-tidy 경고 0, ASan·UBSan 195개 통과, 형식 검사 통과. 커밋 7개가 각각 빌드되고 테스트를 통과한다.
- 수정 전 코드에서 실패하는 새 테스트: 무한대 방향 이동이 위치를 바꾸지 않음, 무한대 방향 투사체 거절, 스냅샷 사이 틱의 이동·정지·피해 셋, 막힌 추격·막힌 귀환, 맵 가장자리 스폰이 있는 Zone 생성 거절, NaN 셀 크기 거절, 한 틱에 두 화살이 잡을 때 먼저 쏜 쪽의 처치. 수정 전 소스에 이 테스트 본문을 붙여 돌려 확인했다. 코덱·지오메트리·입력 큐·걷기 가능 판정 테스트는 새 타입과 함수를 쓰므로 수정 전 코드로는 빌드되지 않는다.
- 원래 맞던 동작을 처음 시험하는 테스트: 궁수가 떠난 뒤 맞은 화살은 몬스터를 잡지만 처치 기록을 남기지 않는다.
- 배포하는 game-data의 맵과 규칙이 새 걷기 가능 검증을 통과한다(로더 테스트).
- end-to-end 연속 실행. 기본: 봇 5개 전원 입장, 모순 0. 곧바로 전투: 시전 37건 모두 수락, 처치 9, DB 처치 영수증 9, Zone의 처치 거절 0, 모순 0. Zone 틱 로그는 `refused=0 superseded=1151`이다. 봇은 이동을 자주 보내서 한 틱에 같은 플레이어의 이동이 여러 개 도착하고, 그중 최신 것만 적용됐다.
