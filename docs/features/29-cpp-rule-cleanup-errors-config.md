## 고민한 선택지와 결정
| 주제 | 선택지 | 결정 |
|---|---|---|
| `Send`의 결과 | `bool` 유지 / `std::expected<void, SendError>` | expected와 `[[nodiscard]]`. 닫힘·직렬화 실패·프레임 초과가 한 `false`에 섞여 있었고, 클라이언트 세션은 결과를 아예 버렸다. 닫히는 연결이 떨군 것은 정상이라 로그하지 않고, 나머지는 로그한다 |
| `optional`로 실패를 알리는 곳(경제 호출 답, lease 갱신 결과, base64 해석) | 모두 expected로 / 실패의 뜻이 하나면 둔다 | 둔다. "답 없음", "갱신 안 됨", "올바른 base64 아님"은 각각 뜻이 하나이고, 받는 쪽이 이유에 따라 다르게 행동하지 않는다. 규칙이 막으려는 것은 여러 실패가 한 값에 섞이는 것이다 |
| 설정 기본값 | 키가 없거나 틀리면 기본값(지금) / 없을 때만 기본값 | 없을 때만. `websocket.enabled = "yes"`가 경고 없이 WebSocket을 껐고, 잘못 쓴 시드가 무작위 시드가 됐다. 없음 자체가 뜻이 있는 키(`zone.rng_seed`, 봇의 Gateway 주소 덮어쓰기)는 `Optional<T>`로 읽어 0과 빈 문자열 같은 표지 값을 없앴다 |
| 범위 검사의 상한 | 숫자 상한을 정함 / 도메인에서 나오는 조건만 | 도메인 조건만. 0이 되면 안 되는 것은 양수, 시뮬레이션 주기는 한 틱이 0이 되지 않을 만큼, Zone 링크 프레임은 클라이언트 프레임 하나를 담을 만큼. 근거 없는 숫자 상한은 또 하나의 매직 넘버가 된다 |
| Zone 종료 | 유예 뒤 이벤트 루프 정지(지금) / 자연 종료 | 자연 종료. Gateway(28)와 같은 방식이다. Zone의 Gateway 링크에도 닫기 상한(`gateway_link.close_linger_ms`)을 두어 끝이 정해져 있다 |
| 재시도 정책 테스트 | `EconomyClient` 앞에 인터페이스 / 정책을 함수로 떼어 냄 | 함수로. 호스트 테스트는 이미 `EconomyGateway` 인터페이스로 경제 전체를 바꿔 끼운다. 비어 있던 것은 재시도 규칙 자체였고, 시도 하나를 함수로 받으면 gRPC 없이 시험된다 |

- `common`: `SendError`·`Describe`, `ConfigSource::Optional`·`Has`, `GetOr`가 `std::expected`를 반환
- `zone/server`:
  - `RetryUntilAnswered`·`IsTransient`와 `EconomyClient`가 그것을 쓰는 형태
  - Gateway 링크 닫기 상한
  - 종료 순서
  - 설정 범위 검사, `rng_seed`는 `std::optional`
  - `zone_server_config`를 호스트 라이브러리로 옮김(테스트가 배포 설정을 읽는다)
- `gateway`: 응답·링크 전송 실패 로그, 설정 범위 검사
- `zone/data`: `stackable`은 불리언이거나 없어야 한다
- 봇: 전송 결과 처리, 프로필 범위 검사, Gateway 주소 덮어쓰기는 `std::optional`
- 설정 파일: Zone에 `gateway_link.close_linger_ms`, `rng_seed`는 주석으로(없으면 무작위)
- README: Zone 종료, 설정 검증 규칙

## 만난 문제
- 배포 설정을 읽는 Zone 설정 테스트가 실패했다. 배포 파일은 `rng_seed = 0`으로 "무작위"를 뜻했는데, `Optional`로 바꾸자 0이 그대로 시드 0이 됐다. 표지 값을 없앤 결과가 배포 설정의 뜻을 바꾼 것이다. 배포 파일에서 키를 주석으로 돌렸다. end-to-end는 환경 변수로 시드를 고정하므로 영향이 없다.
- 같은 일이 봇 프로필에서도 일어났고, 이번에는 end-to-end가 잡았다. 프로필의 `[gateway] host = ""`, `port = 0`은 "덮어쓰지 않음"을 뜻했는데, 엄격한 읽기에서는 진짜 값이 되어 봇 다섯이 모두 빈 주소의 0번 포트로 접속하려다 실패했다. 키를 주석으로 돌렸고, 값이 있다면 빈 주소나 0일 수 없게 했다. 배포 프로필 두 개를 직접 읽는 테스트를 더해, 같은 종류의 변화가 단위 테스트에서 드러나게 했다.
- 테스트 이름 `Run`이 gtest의 `Test::Run`과 겹쳐 빌드되지 않았다. `CallThrough`로 바꿨다.
