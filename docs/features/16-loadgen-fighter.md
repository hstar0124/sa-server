# 16 (4단계) 전투 봇: 몬스터를 사냥하는 Fighter와 전투 end-to-end

## 배경과 목표
15까지로 사람은 뷰어에서 몬스터와 싸울 수 있게 됐지만, 봇은 여전히 걷기만 했다. 전투가 실제 스택에서 깨지지 않는지 매번 손으로 확인할 수는 없고, 나중의 부하 측정도 "걷는 봇"이 아니라 "싸우는 봇"이 필요하다. 이 PR은 봇 두뇌에 전투를 더하고, 전투 봇이 몬스터를 잡아야 통과하는 end-to-end 프로필을 만든다. 이것으로 4단계(전투)가 끝난다. 완료 조건: `fighters.toml`로 돌린 end-to-end가 정해진 수 이상의 처치와 모순 0으로 통과한다.

## 고민한 선택지와 결정
| 주제 | 선택지 | 결정 |
|---|---|---|
| 두뇌의 출력 | 이동 방향만 / 이동과 시전을 함께 담은 `Intent` | `Intent`(방향 + 선택적 시전). 두뇌는 여전히 네트워크를 모르고, 클라이언트가 의도를 메시지로 바꾼다 |
| 두뇌 인터페이스 | 구체 타입마다 분기 / `Brain` 인터페이스 | 인터페이스. 구현이 하나뿐인 인터페이스는 만들지 않는다는 규칙이 있지만, 지금 Wanderer와 Fighter 두 구현이 실제로 쓰이고 프로필이 봇마다 하나를 고른다 |
| 공격 주기 | 서버 쿨타임을 봇이 계산 / 봇은 고정 간격, 쿨타임은 Zone이 강제 | 고정 간격(900 ms). 쿨타임의 진실은 Zone에 있고, 봇이 서버 규칙을 복제하지 않는다. 간격을 쿨타임보다 길게 잡아 정상 상태에서 거절이 0이어야 한다 |
| 대상 선택 | 무작위 / 보이는 가장 가까운 살아 있는 몬스터 | 가장 가까운 몬스터. 결정론적이라 같은 시드면 같은 행동을 한다. 교전 반경 밖이거나 보이는 몬스터가 없으면 배회한다 |
| 판정 기준 | 시전 수 / 처치 수 | 처치 수(`min_kills`). 시전만 세면 사거리 밖에서 헛치는 봇도 통과한다 |
| 가입·로그인 상한 | 상수 10회/분 그대로 / 설정으로 | 설정(`Auth:CredentialAttemptsPerMinutePerAddress`, 기본 10). 봇 전원이 한 주소에서 들어오는 로컬 스크립트만 6000으로 올린다. 운영 기본값은 그대로 낮다 |

## 구현
- `tools/loadgen/bot`: `Intent`·`CastIntent`·`Brain`, `Fighter`. Wanderer도 `Brain`을 구현한다. 관찰(`Observation`)에 자기 체력과 보이는 엔티티의 종류·체력
- `tools/loadgen/client`: 프로필의 역할 수(`wanderers`, `fighters`), 월드 모델의 엔티티 종류·체력·전투 카운터, 보고서의 시전 수락·거절·피해·처치·사망과 `min_kills` 판정, `profiles/fighters.toml`(전투 5 + 배회 1, 40초)
- Zone 안의 프로세스 봇은 Wanderer의 새 출력(`Intent`)에서 방향만 쓴다
- Backend: 가입·로그인 시도 상한을 설정으로. `scripts/e2e-local.sh`, `scripts/dev-stack.sh`가 올린다
- 설계 노트 06 전투: 검증 순서, 투사체 터널링, 몬스터 AI, 생명주기당 한 번의 사망, 이벤트 전달
- README: 구조 표의 loadgen, 네트워크 표의 시도 상한, 전투 절의 노트 링크, 검증과 빌드의 전투 end-to-end. CLAUDE.md에 4단계 완료
- 테스트 5개: Fighter 3개(배회, 접근 후 주기 공격, 교전 반경 밖 무시와 사망 중 대기), 보고서의 처치 기준, 월드 모델의 종류·체력·전투 카운터

## 만난 문제
- 설계 노트와 Backend 주석의 설계 문서 참조를 치환하자, 스크립트가 "18절"을 README의 "앞으로의 설계 방향"으로 바꿨다. 그 절은 README에 아직 없는 내용이라 이전에 뺐다. 커밋 전에 발견했다. 이 주석은 괄호를 지워도 뜻이 통해서 지웠고, 스크립트는 README에 없는 절(범위, 무엇을 만드나, 앞으로의 설계 방향)로 바꾸는 대신 검토 표시를 내도록 고쳤다. develop에 같은 참조가 없는 것도 확인했다.
- 설계 노트 06은 이전 저장소에서 잰 "40초 동안 16마리"를 담고 있었다. 이 저장소에서 다시 돌린 값으로 바꿨다. 노트가 노트만으로 읽히도록 서두에 프로젝트와 Zone·Gateway 배경을 더했고, 이벤트 수신자 설명을 15에서 고친 실제 동작에 맞췄다.
