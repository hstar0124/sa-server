# 45 (8단계) Zone 이전: 포털, 출발, 체크포인트 주기, Gateway로 넘기기

## 배경과 목표
8단계는 두 번째 Zone과 소유권 이전이다. 캐릭터의 소유자는 Backend의 소유권 행이 정한다. 행에는 Zone 인스턴스와 세대(`owner_epoch`)가 있고, Zone은 lease로 자기가 살아 있음을 알린다. 지금까지 이렇게 왔다.
- 42: 계약, 테이블, 두 번째 지도와 포털
- 43: Backend가 체크포인트 저장과 이전을 한 트랜잭션으로 처리
- 44: Gateway가 `SessionTransfer`를 받으면 세션을 도착 Zone에 다시 붙임

이 PR은 그 사이를 잇는 Zone 쪽이다. 시뮬레이션은 포털과 출발을 판정하고, 호스트는 Backend에 체크포인트와 이전을 요청하고 결과를 Gateway에 넘긴다. 결정은 ADR-0010을 따른다.

완료 조건:
- 포털 반경 안에서만 떠날 수 있고, 떠나는 동안 캐릭터는 아무것도 하지 못한다.
- Backend가 옮겼으면 출발 Zone은 캐릭터를 지우고 Gateway에 도착지를 알린다. 옮기지 않았으면 캐릭터를 풀어 준다.
- 응답을 잃어도 캐릭터가 두 Zone에 걸리거나 두 번 옮겨지지 않는다.
- 움직인 캐릭터의 위치는 주기마다 저장되고, 나갈 때도 저장된다.
- 한 캐릭터는 한 Zone에 몸이 하나다.

## 고민한 선택지와 결정
| 주제 | 선택지 | 결정 |
|---|---|---|
| 이전 ID | 요청마다 난수 / 캐릭터·세대·요청 ID의 다이제스트 | 다이제스트. 답을 잃은 뒤 클라이언트가 같은 요청 ID로 다시 보내면 같은 이전 ID가 나가고, Backend는 저장된 결정(`ALREADY_TRANSFERRED`)을 돌려준다. 난수면 두 번째 시도가 새 이전이 된다. 그런데 첫 시도가 이미 커밋했다면 권한 없음으로 거절된다. 그러면 Backend는 캐릭터를 옮겼는데 출발 Zone은 그대로 붙잡고 있게 된다 |
| 답이 없을 때 | 세션 종료 / 풀어 주고 "모름" | 풀어 주고 "모름". 획득과 같은 규칙이다. 결과를 기억하지 않으니 같은 요청 ID의 재시도가 다시 Backend에 묻는다. 그사이 캐릭터가 실제로 옮겨졌다면 다음 체크포인트나 처치가 권한 없음을 받아 세션이 끝난다 |
| 대기 중 재시도 | 결과를 "처리 중"으로 기억 / 떠나는 상태에서 답 | 떠나는 상태에서 답한다. 획득이 예약에서 답하는 것과 같다. 다른 요청이 몰려도 재시도 기록에서 밀려나지 않는다 |
| 명령 경로 | 바로 처리 / 스킬·획득과 같은 큐 | 같은 큐. 틱당 예산과 플레이어별 상한을 똑같이 받는다 |
| 체크포인트 | 주기마다 모든 세션 / 움직인 세션만 | 움직인 세션만. 서 있는 캐릭터를 15초마다 다시 쓰지 않는다. 답을 받지 못한 저장은 다음 주기에 다시 보낸다 |
| 나갈 때 위치 | 주기 저장만 / 나가기·링크 끊김에도 저장 | 저장한다. 소유권은 세션이 끝나도 남으므로 Backend가 받아 준다. 마지막 주기 이후 움직인 거리를 잃지 않는다 |
| 같은 캐릭터 부착 | 같거나 낮은 세대만 거절 / 높은 세대면 옛 세션도 내보냄 | 내보낸다. 다른 Gateway로 다시 들어왔는데 옛 Gateway의 링크가 아직 살아 있으면, 그대로 두면 한 캐릭터가 몸 둘로 시뮬레이션된다 |
| Backend 호출 재시도 | 클라이언트마다 / 공용 정책 | 공용(`backend_call.hpp`). 경제와 배치 호출이 모두 다시 보내도 안전하다. 설정 이름은 `backend.economy_call_attempts`에서 `backend.call_attempts`로 바꿨다 |

## 옮기면서 고친 것
- 이전 이력은 이전 ID를 요청마다 새로 만들었다. 답을 잃고 재시도하면, Backend가 이미 옮긴 캐릭터를 출발 Zone이 계속 시뮬레이션할 수 있었다. 이전 ID를 요청에서 파생한다. 재시도 테스트가 두 요청의 ID가 같음을 확인한다.
- 이전 이력은 Backend 호출 실패 시 재시도가 없었다(이전·체크포인트 모두). 경제 호출과 같은 재시도 정책을 쓴다.
- 이전 이력은 높은 세대의 부착이 와도 옛 세션을 두어, 한 캐릭터가 몸 둘이 될 수 있었다.
- 이전 이력은 체크포인트 권한 거절을 세었을 뿐 아무것도 하지 않았다. 이제 처치·획득처럼 세션을 끝낸다. 단, 이전이 진행 중이면 그 결과에 맡긴다. 이전 직전에 보낸 저장이 이전 커밋 뒤에 도착해 거절되는 경우, 성공한 이동 중에 킥되지 않게 하기 위해서다.
- 이전 이력은 Backend가 다른 Zone이나 낡은 세대를 답해도 그대로 Gateway에 넘겼다. Gateway(44)는 그런 통지를 무시하므로 세션이 갈 곳을 잃는다. 이제 세션을 끝낸다.
- 이전 이력은 서 있는 캐릭터도 주기마다 저장했고, 나갈 때는 저장하지 않았다.
- 이전 이력은 대기 중인 이전을 "처리 중" 결과로 재시도 기록에 넣었다가 실패 시 지웠다. 현재 저장소의 획득과 같은 방식(상태에서 답하기)으로 맞췄다.
- 이전 이력은 체크포인트 틱 수를 `* hz / 1000`으로 계산했다. `std::chrono`로 계산하고, 한 틱보다 짧은 주기는 시작할 때 거절한다.
- 지도 검증 주석은 "자기 Zone이 아닌 목적지"를 약속했지만 지도는 자기 Zone ID를 모른다. Zone 생성 때 확인한다.
- `codec.hpp`에서 획득 요청 키의 주석이 처치 ID 함수 위에 붙어 있던 것을 바로잡았다.

## 만난 문제
- [이슈 018](../issues/018-e2e-bots-reuse-characters-across-runs.md): 봇이 실행마다 같은 캐릭터를 다시 써서 end-to-end가 이전 실행에 좌우됐다. 쌓인 아이템으로 looters의 인벤토리가 꽉 차 획득 판정이 실패했다. 체크포인트가 생기면서 영향이 커졌다. 두 번째 실행부터 봇이 지난 실행의 마지막 위치에서 시작하기 때문이다. 이름을 만드는 시드를 행동 시드와 분리해 이 PR에서 고쳤다.
