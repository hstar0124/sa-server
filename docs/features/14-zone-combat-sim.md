# 14 (4단계) 전투 시뮬레이션: 스킬·투사체·피해·사망·몬스터 AI

## 배경과 목표
13에서 들인 클래스·스킬·몬스터 정의를 Zone 시뮬레이션이 실제로 쓰게 한다. 스킬 요청의 검증부터 시전, 발동, 피해, 사망과 부활, 몬스터의 추적·공격·귀환까지 소켓·시계를 모르는 시뮬레이션 코어 안에서 틱 단위로 돈다. Zone 서버는 시작할 때 콘텐츠를 읽고, 콘텐츠에 없는 클래스의 캐릭터는 받지 않는다.

범위는 시뮬레이션과 Zone 시작 경로까지다. 클라이언트의 스킬 메시지를 시뮬레이션에 넘기고 결과·전투 이벤트·체력을 클라이언트에 보내는 호스트 연결은 다음 PR이다. 완료 조건: 단위 테스트로 검증 순서, 중복 요청, 발동 재검증, 투사체, 한 번뿐인 사망, 몬스터 상태 전이, 귀환 시 회복을 확인하고, 몬스터가 있는 맵에서 실제 스택이 정합성 오류 없이 돈다.

## 고민한 선택지와 결정
| 주제 | 선택지 | 결정 |
|---|---|---|
| 전투 로직 위치 | 호스트(네트워크 계층) / 순수 시뮬레이션 | 시뮬레이션. 난수는 주입받고 시간은 틱이라 같은 시드와 입력이면 같은 결과다. 테스트 하나가 이것을 직접 확인한다 |
| 파일 구성 | `zone.cpp` 하나 / 관심사별 | `zone.cpp`(멤버십·입력·관심·뷰), `zone_combat.cpp`(스킬·투사체·피해·사망), `zone_monsters.cpp`(스폰·AI). 한 `Zone` 클래스의 구현을 나눈 것이고 계층을 더하지 않았다 |
| 중복 요청 | 무시 / 최근 결과 기억 | 플레이어마다 최근 요청 ID와 결과를 기억한다. 다시 온 요청은 처음과 같은 답(수락 또는 같은 거절 사유)을 받고 상태는 그대로다 |
| 마나·쿨타임 시점 | 둘 다 시작 / 둘 다 발동 / 마나는 시작, 쿨타임은 발동 | 마나는 시작할 때 써서 같은 마나로 두 번 시전하지 못하게 한다. 쿨타임은 발동할 때 시작해 시전이 끊겨도 스킬이 잠기지 않게 한다 |
| 발동 재검증 | 시작할 때만 / 발동할 때 다시 | 다시. 시전 시간 동안 대상이 죽거나 멀어질 수 있다. 실패한 발동도 마나는 쓴 것으로 친다 |
| 사망 처리 | 피해마다 체력 0 확인 / 살아 있을 때만 피해 적용 | 살아 있을 때만. 같은 틱에 공격 두 개가 겹쳐도 사망과 처치는 한 번이다. 처치 보상을 붙일 때 이 한 번이 근거가 된다 |
| 몬스터 판단 주기 | 매 틱 / 5 Hz, 개체별 분산 | 5 Hz, 슬롯 번호로 시점을 엇갈린다. 이동은 매 틱이라 움직임은 부드럽고, 판단 비용은 매 틱의 4분의 1이다 |
| 리시 | 귀환만 / 귀환 뒤 체력 회복 | 회복. 리시를 이용해 몬스터를 조금씩 깎아 잡는 것을 막는다 |
| 이벤트 수신자 | 호스트가 결정 / 시뮬레이션이 결정 | 시뮬레이션. 대상을 시야에 둔 플레이어와 공격자에게 보낸다. 호스트는 직렬화와 라우팅만 한다 |
| 모르는 클래스 | 기본값으로 세우기 / 입장 거절 | 거절. Zone 링크 계약에 `REJECT_REASON_UNKNOWN_CLASS`를 더했다. 체력이 없는 캐릭터를 맵에 세우지 않는다 |

## 구현
- `zone/sim`: `events.hpp`(거절 사유, 명령 결과, 전투 이벤트, 수신자 지정), `entities.hpp`(스킬 명령과 대상, 엔티티 체력), `zone.hpp/.cpp`, `zone_combat.cpp`, `zone_monsters.cpp`. 뷰는 이제 자기 자신을 항상 담는다
- `zone/server`: 시작할 때 콘텐츠와 전투 규칙을 읽고 버전을 로그에 남긴다. 모르는 클래스는 입장을 거절한다. 설정에 `content.dir`
- 계약: `zone_link.proto`의 `REJECT_REASON_UNKNOWN_CLASS`
- 테스트: 전투 11개, 몬스터 5개, 모르는 클래스 거절 호스트 테스트 1개. 이전 이력은 이 거절 테스트를 다음 피처(15)에서 넣었다. 동작이 들어오는 PR에 테스트도 있어야 해서 여기서 더했고, 15에서 겹치는 쪽을 지웠다
- README: 구조 표, 데이터의 기준, 틱 흐름, 전투 절(요청 처리 순서, 사망과 부활, 몬스터 상태 기계)
- 이전 이력의 설계 문서 참조를 README 제목으로 바꿨고, 치환이 놓친 숫자 참조를 정리했다(아래 문제)
