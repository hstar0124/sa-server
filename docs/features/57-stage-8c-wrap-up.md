# 57 (8c) 8c 마무리: 용량 사다리 50~2,000명, ADR-0012, 보고서 04, 설계 노트 12

## 배경과 목표
8c(밀집 처리량)는 52~56으로 기능이 다 들어왔다.
- 52 느린 클라이언트 끊기
- 53 스냅샷 직접 인코딩
- 54 dead reckoning과 시야 주기 관심 계산
- 55 관심 계산 비용
- 56 링크 세그먼트 상한

이 PR은 단계를 마치며 용량 사다리를 다시 재고, 결정과 과정과 숫자를 문서로 남기고, 작업 규칙 문서(CLAUDE.md)에 8c 완료를 적는다. 원래 계획의 "Gateway 다중 스레드(56)"는 측정으로 보류했고, 그 번호는 2,000명에서 드러난 링크 교착이 썼다.

## 고민한 선택지와 결정
| 주제 | 선택지 | 결정 |
|---|---|---|
| ADR 범위 | dead reckoning만 / 관심 계산 주기와 사건 수신자까지 | 함께. 클라이언트가 외삽해야 한다는 프로토콜 약속, 관심 집합이 최대 한 틱 오래될 수 있다는 약속, 사건은 known 집합에 간다는 약속이 한 묶음이다. 세그먼트 상한은 결정이 아니라 고장 수리라 이슈 021에 둔다 |
| 용량 사다리의 끝 | 1,000명(지금까지) / 2,000명 | 2,000명까지. 1,000명에서는 더 볼 것이 없었고, 2,000명에서 관심 계산의 증가율과 링크 교착이 드러났다. 작업 규칙의 기준선 범위도 50~2,000명으로 고쳤다 |
| Gateway 다중 스레드 | 이번에 / 보류 | 보류. 2,000명에서 Gateway가 0.40코어다. 11단계에서 코어당 인원 목표를 정할 때 다시 잰다 |

## 구현
- [ADR-0012](../adr/0012-dead-reckoning-and-interest-on-view-ticks.md): 움직임은 dead reckoning으로 보고하고, 관심 계산은 시야 주기에 나눠 한다
- [보고서 04](../reports/04-dense-throughput.md): 조치별 효과(1,000명·2,000명)와 8c 뒤 용량 사다리
- [설계 노트 12](../design-notes/12-dense-throughput.md): 무엇이 비쌌나, 어떤 순서로 고쳤나, 이전 이력의 장치 다섯 개를 왜 뺐나, 2,000명 링크 교착을 원인까지 따라간 과정
- README: "Zone의 한 틱"에 dead reckoning·관심 계산·세그먼트 상한, "밀집" 소절, 성능 표 세 줄, 봇과 뷰어의 외삽
- CLAUDE.md: 단계 목록에 8c 완료, 기준선 범위 50~2,000명
