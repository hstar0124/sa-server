# 008 릴리스 버전 한 줄이 CI 의존성 캐시를 무효로 만든다

- 상태: 해결 (17의 `ci: fall back to the newest dependency cache ...` 커밋)
- 발견: [17 CI 의존성 캐시](../features/17-ci-cache-miss-on-version-bump.md), 2026-10-19, 0.2.0 릴리스를 준비하다
- 영향: 버전을 올리는 릴리스 PR마다 의존성 잡이 캐시를 찾지 못하고 gRPC·protobuf·abseil을 처음부터 빌드한다. 차가운 빌드는 2시간 15분이었다([006](006-ci-dependency-cache-scoped-to-one-pull-request.md)). 그동안 릴리스 PR은 병합 조건을 채우지 못한다

## 증상
아직 일어나지 않았다. 0.2.0 릴리스 커밋을 준비하며 버전이 적힌 곳을 찾았더니 루트 `CMakeLists.txt`와 `vcpkg.json` 두 곳이었다. CI의 의존성 캐시 키는 아래와 같고, 복원 단계에 대체 키가 없다.

```
key: vcpkg-${{ env.VCPKG_TRIPLET }}-${{ hashFiles('vcpkg.json') }}
```

`vcpkg.json`의 `version-string`을 0.1.0에서 0.2.0으로 바꾸면 키가 달라지고 복원은 실패한다. 0.1.0 때는 버전이 처음부터 0.1.0이라 버전 줄을 바꾸지 않았고, 그래서 드러나지 않았다.

## 원인 분석
- 캐시에 든 것은 설치 트리가 아니라 vcpkg의 바이너리 아카이브다(`VCPKG_BINARY_SOURCES`의 files 공급자). 아카이브는 패키지마다 ABI 해시로 이름이 붙는다. ABI는 포트 파일, 트리플릿, 컴파일러, 의존 패키지의 ABI로 정해지고, 최상위 매니페스트의 버전은 들어가지 않는다.
- 로컬에서 확인했다. gcc-toolset-14 안에서 원래 매니페스트와 버전을 뺀 매니페스트로 각각 `vcpkg install --dry-run`을 돌리면 둘 다 "already installed"다.
- 처음 시험은 툴체인 밖에서 돌려 "will be rebuilt"가 나왔다. 시스템 컴파일러(`/usr/bin/c++`)를 잡아 컴파일러 해시가 달랐기 때문이고, 매니페스트와는 무관했다.
- 따라서 키가 바뀌어도 이전 캐시의 아카이브를 그대로 쓸 수 있다. 막는 것은 키의 정확 일치뿐이다.

## 원인
캐시 키가 "의존성이 바뀌었나"가 아니라 "vcpkg.json이 바뀌었나"를 물었고, 키가 어긋났을 때 되돌아갈 곳이 없었다. 제품 버전이 의존성 매니페스트에 같이 있었다.

## 해결
- 의존성 잡의 복원 단계에 `restore-keys: vcpkg-<트리플릿>-`를 더했다. 정확한 키가 없으면 같은 트리플릿의 가장 최근 캐시를 복원하고, vcpkg가 ABI가 같은 아카이브는 그대로 쓰고 바뀐 패키지만 빌드한다. 끝나면 새 키로 저장한다. C++ 세 잡은 계속 정확한 키를 요구한다. 그 잡들보다 의존성 잡이 먼저 새 키를 저장하기 때문이다.
- 제품 버전을 `vcpkg.json`에서 뺐다. vcpkg는 최상위 매니페스트에 버전을 요구하지 않는다. 버전은 루트 `CMakeLists.txt`의 `project(... VERSION ...)` 한 곳에만 둔다. 이제 릴리스 커밋은 의존성 매니페스트를 건드리지 않는다.
- 대안으로 키를 `dependencies`와 `builtin-baseline`만의 해시로 계산하는 방법이 있었다. 키를 만드는 단계가 하나 늘고, 의존성을 하나라도 올리면 결국 처음부터 빌드하는 문제가 남는다. 대체 키는 그 경우에도 바뀐 패키지만 빌드한다.
- 대가도 있다. 대체 키로 복원한 캐시에는 더 이상 쓰지 않는 옛 아카이브가 남고, 새 키로 함께 저장된다. 의존성을 올릴 때마다 캐시가 조금씩 커진다.

## 재발 방지
- 이 수정을 담은 PR이 바로 그 경로를 지난다. `vcpkg.json`이 바뀌어 정확한 키가 없으니, 의존성 잡은 대체 키로 develop의 캐시를 복원해야 한다. 그 실행 시간을 17의 "검증"에 적었다.
- CONTRIBUTING.md의 릴리스 항목에 "버전은 루트 CMakeLists.txt 한 곳"을 적었다.
