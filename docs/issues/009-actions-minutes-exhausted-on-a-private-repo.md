# 009 비공개 저장소의 Actions 무료 시간이 바닥나 CI 잡이 시작되지 않음

- 상태: 해결 (저장소 공개 전환, 2026-10-19)
- 발견: [17 CI 의존성 캐시](../features/17-ci-cache-miss-on-version-bump.md), 2026-10-19
- 영향: 모든 PR의 필수 검사가 실패해 룰셋상 아무것도 병합할 수 없다

## 증상
PR #19의 첫 CI 실행에서 `.NET`과 `C++ dependencies`가 2초 만에 실패했고, C++ 세 잡은 건너뛰었다. 실행 요약의 주석은 아래와 같았다.

```
The job was not started because recent account payments have failed or your spending limit needs to be increased.
```

## 원인 분석
- 이 PR이 건드리지 않은 `.NET` 잡까지 2초 만에 실패했다. 코드나 워크플로 문법 문제라면 잡이 시작은 되거나, 실행 자체가 워크플로 오류로 떠야 한다. 주석이 "잡이 시작되지 않았다"고 직접 말했다.
- 저장소는 비공개였다. GitHub 무료 계정은 비공개 저장소의 Actions에 월 2,000분을 준다.
- 사용량 API는 토큰 권한(`user` 범위)이 없어 읽지 못했다. 대신 이 저장소의 모든 실행에서 잡마다 시작·끝 시각을 받아, 과금처럼 잡별로 분 단위 올림해 합했다. 잡 182개, 약 2,034분이었다. 의존성을 처음부터 빌드한 실행 몇 번(각 2시간 넘게)이 대부분을 차지했다.

## 원인
비공개 저장소에서 월 무료 시간을 넘겼고, 추가 결제 한도가 0이라 GitHub이 잡을 막았다.

## 해결
저장소를 공개로 바꿨다. 공개 저장소는 GitHub 기본 러너를 시간 제한 없이 쓴다. 포트폴리오라 공개할 저장소였다. 바꾸기 전에 이력 전체(커밋 256개)를 확인했다. `.env` 파일이 커밋된 적이 없고, 비밀 값처럼 보이는 줄도 없다. 설정 파일에는 빈 값과 `change-me` 자리표시만 있다. 다시 돌린 실행은 정상으로 시작했다.

다른 길도 있었다.
- 추가 결제 한도: 지금 사용량이면 월 2,000분 정도가 더 필요하다.
- 다음 결제 주기까지 대기: 그동안 아무것도 병합할 수 없다.
- 미니 PC를 자체 러너로 등록: 무료지만 CI가 이 PC에 묶이고, 공개 저장소에서는 외부 PR의 코드가 이 PC에서 돈다.

## 재발 방지
- 공개 저장소라 시간 한도가 없다. 다시 비공개로 돌리면 이 한도가 돌아온다는 것을 CONTRIBUTING.md의 도구 절에 적었다.
- 시간을 가장 많이 쓰던 "의존성 처음부터 빌드"는 [008](008-version-bump-invalidates-the-ci-dependency-cache.md)의 대체 키로 줄였다.
