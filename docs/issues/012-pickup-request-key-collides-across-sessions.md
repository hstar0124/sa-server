# 012 획득 요청 키가 세션을 넘어 겹쳐 정상 요청이 거절됨

- 상태: 해결 (23의 `fix(zone): derive the pickup idempotency key ...` 커밋)
- 발견: [23 Zone 드롭과 획득](../features/23-zone-drops-pickup.md), 2026-10-20. 이전 이력에서 나중에 고친 결함을 옮기기 전에 찾았다
- 영향: 같은 캐릭터로 다시 접속한 플레이어의 아이템 획득이 이전 세션에 쓴 요청 번호와 겹치면 `REQUEST_MISMATCH`로 거절된다. 플레이어는 아이템을 집을 수 없다

## 증상
이전 이력에서 이 피처 뒤에 같은 파일을 고친 커밋을 찾자 하나가 나왔다. 그 커밋의 설명이 증상이다. 클라이언트가 세션마다 요청 번호를 처음부터 다시 세는데, Backend는 예전 세션에 저장한 결과와 같은 키의 다른 요청으로 보고 `REQUEST_MISMATCH`를 돌려줬다.

## 원인 분석
- Zone은 Backend에 저장할 16바이트 요청 키를 "캐릭터 ID 8바이트 + 요청 번호 8바이트"로 만들었다. 주석은 "둘을 합치면 캐릭터 일생 동안 유일하다"였다.
- 요청 번호는 클라이언트가 정한다. 봇과 뷰어 모두 세션마다 1부터 센다. 그래서 두 번째 세션의 첫 획득 키는 첫 세션의 첫 획득 키와 같다.
- Backend는 22에서 정한 대로 같은 키에 다른 본문이 오면 거절한다. 아이템 ID가 다르니 본문 해시가 다르다.
- 같은 세션 안의 재시도는 키가 같아야 한다. 그래야 응답을 잃은 Zone이 다시 보낼 때 저장된 결과를 받는다.

## 원인
"캐릭터 일생 동안 유일"이라는 가정이 틀렸다. 요청 번호는 세션 안에서만 유일하다.

## 해결
요청 키를 캐릭터 ID, 소유권 세대(`owner_epoch`), 요청 번호를 HMAC-SHA256으로 묶은 다이제스트로 바꿨다. 소유권 세대는 입장할 때마다 오르므로 세션마다 다르고, 같은 세션 안의 재시도는 같은 키를 만든다. 이전 이력의 수정 커밋을 이 PR로 당겨 왔다.

## 재발 방지
- 코덱 테스트가 "같은 세션의 재시도는 같은 키, 다른 세대는 다른 키"를 고정한다.
- 이전 이력을 옮길 때 같은 파일의 다음 수정 커밋을 확인하는 단계([011](011-backend-content-dir-resolved-inside-its-own-directory.md)의 재발 방지)가 이번에 이 결함을 찾았다.
