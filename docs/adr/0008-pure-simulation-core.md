# ADR-0008: Zone 시뮬레이션은 시계·난수 주입형 순수 라이브러리

- 상태: Accepted
- 날짜: 2026-10-12

## 맥락
문서 7.3절은 "전체 결정론적 재현은 초기 필수가 아니다"라고 했다. 그러나 이동·충돌·AOI·스킬 판정의 단위 테스트와 장애 재현에는 **같은 입력에 같은 결과**가 필요하다. 19절도 전투·이동 계산을 네트워크와 분리하라고 요구한다.

## 결정
1. `server/cpp/zone`은 두 타깃으로 나눈다. `zone_sim`(정적 라이브러리, I/O 없음)과 `zone_server`(실행 파일, Asio·gRPC·config).
2. `zone_sim`은 시계(`TickClock`), 난수(`Rng`), 콘텐츠 데이터(`GameData`)를 **생성자에서 주입**받는다. `std::chrono::steady_clock`, `std::random_device`, 파일 I/O를 직접 호출하지 않는다.
3. 한 Zone의 상태는 **단일 실행 흐름**만 변경한다(7.1절). `zone_sim`은 스레드를 만들지 않는다. 비동기 결과는 `zone_server`가 큐로 넣어 tick에서 소비한다.
4. 테스트는 입력 시퀀스를 주고 N tick 진행 후 상태를 단언한다. 부동소수점은 고정된 연산 순서를 유지한다. 플랫폼 간 비트 동일성은 보장 목표가 아니다(같은 빌드·같은 머신에서 재현되면 충분).
5. 네트워크 역직렬화 결과를 `zone_sim` 명령 타입으로 변환하는 층은 `zone_server`에 둔다. `zone_sim`은 Protobuf 타입을 모른다.

## 결과
- 수천 tick 테스트가 밀리초에 돈다. 밀집 전투 시나리오를 CI에서 돌릴 수 있다.
- Protobuf↔도메인 변환 코드가 한 층 더 생긴다. 이것이 "도메인은 I/O를 모른다" 규칙의 비용이다.
