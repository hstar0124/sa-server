# 05 순수 시뮬레이션 코어

Zone의 게임 로직(`server/cpp/zone/sim`)은 소켓, 시계, 난수 장치, 파일, Protobuf를 모른다. 시계는 고정 주기 틱으로, 난수는 시드 있는 `Rng`로, 콘텐츠는 이미 파싱된 구조체로 주입받는다 (ADR-0008).

## 왜

1. **재현.** 같은 시드와 같은 입력 순서면 같은 상태가 나온다. 테스트가 이를 고정한다. 장애 보고에 시드와 입력 로그만 있으면 그 상태를 다시 만들 수 있다.
2. **속도.** 수천 틱 테스트가 밀리초에 돈다. 밀집 전투 시나리오를 CI에서 돌릴 수 있다.
3. **경계.** 네트워크 코드와 게임 규칙이 섞이지 않는다. Protobuf ↔ 도메인 변환은 `zone/server/codec`에 따로 있고, 그것도 순수 함수라 따로 테스트된다.

## 안에 있는 것

- **이동**: 입력 방향을 정규화해 최대 속도로 적분한다. 이전 이하의 입력 순번은 버리고 집계한다. 틱당 명령 예산을 넘는 입력은 다음 틱으로 미룬다. 설계 문서 7.2절의 "뒤처진 틱을 무제한 따라잡지 않는다"는 `FixedStepScheduler`가 상한 초과분을 버리고 센다.
- **충돌**: 맵 경계와 AABB 장애물에 축 분리 방식으로 처리해 벽에 붙지 않고 미끄러진다.
- **관심 영역(AOI)**: 균일 격자로 후보를 뽑고 정확한 거리로 거른다. 진입 반경과 이탈 반경을 분리한 히스테리시스로 경계에서 깜빡이지 않는다.
- **뷰 델타**: 플레이어별로 "알려준 집합"과 "현재 관심 집합"을 정렬 유지하고 한 번의 병합으로 spawned, updated, despawned를 만든다. 설계 문서 6.3절 WorldSnapshot에 그대로 대응한다.

## 밖에 있는 것

- 틱을 실제 시간에 맞추는 Asio 타이머 (`TickRunner`).
- Gateway 링크, 세션 테이블, 스냅샷 직렬화 (`ZoneHost`, `GatewayLink`).
- game-data TOML 로딩 (`zone/data`).
- Backend lease 갱신.

## 테스트가 증명하는 것

- 이동 속도·정규화·정지, 맵 밖으로 못 나감, 벽 따라 미끄러짐, 오래된 입력 무시, 명령 예산 이월.
- 같은 시드·같은 입력 → 같은 위치.
- 진입 20 m에서 보이기 시작하고 25 m를 넘어야 사라진다. 그 사이 밴드에서는 깜빡이지 않는다.
- 떠난 플레이어는 관찰자의 다음 뷰에 despawned로 나타난다.
- 두 명이 서로를 대칭으로 본다.

## 다음에 들어올 것
