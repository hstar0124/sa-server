# 05 순수 시뮬레이션 코어

## 배경

이 프로젝트의 지역 서버(Zone)는 플레이어 이동·충돌·관심 영역·스킬·몬스터 AI를 20 Hz 고정 틱으로 계산하는 C++ 프로세스다. 그 계산을 담당하는 코드(`server/cpp/zone/sim`)는 **소켓, 시계, 난수 장치, 파일, Protobuf를 모른다.** 시계는 고정 주기 틱으로, 난수는 시드 있는 생성기로, 콘텐츠는 이미 파싱된 구조체로 주입받는다. 이 글은 그렇게 만든 이유와 그 결과 얻은 것을 설명한다.

## 왜

1. **재현.** 같은 시드와 같은 입력 순서면 같은 상태가 나온다. 테스트가 이를 고정한다. 장애 보고에 시드와 입력 로그만 있으면 그 상태를 다시 만들 수 있다.
2. **속도.** 수천 틱 테스트가 밀리초에 돈다. 밀집 전투 시나리오를 CI에서 돌릴 수 있다.
3. **경계.** 네트워크 코드와 게임 규칙이 섞이지 않는다. Protobuf와 도메인 타입 사이의 변환은 호스트 쪽의 순수 함수 하나(`codec`)에 모여 있고, 그것도 따로 테스트된다.

## 안에 있는 것

- **이동**: 입력 방향을 정규화해 최대 속도로 적분한다. 입력마다 붙는 순번이 이전 이하이면 버리고 집계한다. 틱당 명령 예산을 넘는 입력은 다음 틱으로 미룬다. 서버가 뒤처졌을 때 밀린 틱을 무제한 따라잡지 않도록, 고정 주기 스케줄러가 상한 초과분을 버리고 센다.
- **충돌**: 맵 경계와 축 정렬 사각형 장애물에 대해 "전체 이동 → x만 → y만" 순으로 시도해 벽에 붙지 않고 미끄러진다.
- **관심 영역(AOI)**: 맵을 균일 격자로 나눠 후보를 뽑고 정확한 거리로 거른다. 진입 반경 40 m와 이탈 반경 45 m를 분리한 히스테리시스로, 경계에 선 엔티티가 매 틱 나타났다 사라졌다 하지 않는다.
- **뷰 델타**: 플레이어별로 "이미 알려준 집합"과 "현재 관심 집합"을 정렬해 유지하고, 한 번의 병합으로 새로 보인 것·움직인 것·사라진 것을 만든다. 이것이 그대로 클라이언트 스냅샷이 된다.
- **전투**: 스킬 검증·시전·투사체·피해·사망·몬스터 AI. [06 전투](06-combat.md)에서 따로 설명한다.

## 밖에 있는 것

- 틱을 실제 시간에 맞추는 Asio 타이머.
- Gateway와의 링크, 세션 테이블, 스냅샷 직렬화.
- game-data TOML 로딩.
- Backend lease 갱신.

## 테스트가 증명하는 것

- 이동 속도·정규화·정지, 맵 밖으로 못 나감, 벽 따라 미끄러짐, 오래된 입력 무시, 명령 예산 이월.
- 같은 시드·같은 입력 → 같은 위치. 전투가 섞여도 같다.
- 진입 20 m에서 보이기 시작하고 25 m를 넘어야 사라진다. 그 사이에서는 깜빡이지 않는다.
- 떠난 플레이어는 관찰자의 다음 뷰에 사라진 것으로 나타난다.
- 두 명이 서로를 대칭으로 본다.

## 비용

Protobuf↔도메인 변환 코드가 한 층 더 생긴다. 이것이 "도메인은 I/O를 모른다"의 값이다. 부동소수점 연산 순서를 고정해 같은 빌드·같은 머신에서의 재현을 보장하지만, 플랫폼 간 비트 동일성은 목표가 아니다.
