# tests/integration

정합성 통합 테스트는 .NET 솔루션 안의 `server/dotnet/tests/GameBackend.IntegrationTests/`에 있다. 저장소 전체 컴파일 정책(Directory.Build.props)과 패키지 버전(Directory.Packages.props)을 상속받기 위해서다.

- 실제 PostgreSQL을 Testcontainers로 띄우고 `database/migrations/`를 적용한 뒤 실행한다.
- 각 테스트는 HTTP 상태 코드가 아니라 **DB 상태(소유자 수, 잔액, 원장, Inbox)**를 단언한다.
- 이벤트 파이프라인 시나리오(발행 중 종료, 소비 중 종료)는 실제 Kafka도 필요해서 `server/dotnet/tests/EventWorker.Tests/`에 있다. 같은 방식으로 PostgreSQL과 Kafka를 Testcontainers로 띄운다.
- C++ 쪽(Zone·Gateway) 통합 테스트가 생기면 이 디렉터리에 둔다.

## 반드시 통과할 정합성 시나리오

아래 표가 통합 테스트 목록이다. 해당 기능이 들어오는 단계에서 테스트가 함께 들어오고, 테스트 없는 정합성 코드는 미완성으로 본다.

| 테스트 | 주입 조건 | 기대 결과 | 단계 |
|---|---|---|---|
| 입장 1회 소비 | 같은 티켓을 두 Gateway가 동시에 제출 | 한 건만 승인, 세션·소유자 하나 | 1 |
| Zone 재시작 | 옛 lease가 살아 있는 동안 같은 Zone ID의 새 인스턴스 등록 | 새 인스턴스에만 배정, 옛 인스턴스의 갱신·지급 거절 | 3 |
| 동시 획득 | 두 요청이 같은 개별 아이템을 경쟁 | 최종 소유자 한 명 | 5 |
| 재화 동시 차감 | 잔액보다 큰 합계의 요청 | 음수 잔액 없음 | 5·9 |
| 요청 중복 | 같은 request_id를 반복 전달 | 자산 효과 한 번 | 5 |
| ID 오용 | 같은 request_id, 다른 본문 | 거절 | 5 |
| 응답 유실 | 커밋 직후 연결 종료 | 재조회로 기존 결과 확인 | 5 |
| 발행 중 종료 | Kafka ack 후 Outbox 표시 전 종료 | 이벤트 중복 가능, 소비 효과는 한 번 | 6 |
| 소비 중 종료 | DB 커밋 후 offset 커밋 전 종료 | Inbox로 업무 변경 중복 방지 | 6 |
| 이전 지연 | 이전 Zone의 늦은 저장 전달 | 낮은 owner_epoch 거절 | 8 |
| 도착 실패 | 소유권 이전 전후 도착 Zone 종료 | 한 소유자로 복구 | 8 |
| 거래 확정 | 양쪽 동의, 동시 동의, 바뀐 제안, 확정 요청 재전달 | 양쪽 자산 보존, 확정 한 번, 바뀐 제안은 동의를 지움 | 9 |
| 거래 잠금 | 한 캐릭터·한 아이템을 두 거래에, 두 캐릭터가 서로 동시에 열기 | 열린 거래 하나, 교착 없음 | 9 |
| 가득 찬 맞교환 | 둘 다 가득 찬 인벤토리끼리 하나씩 교환 | 확정, 칸마다 아이템 하나, 용량 이상의 칸에 남은 것 없음 | 9 |
| 확정 중 거절 | 첫 차감 뒤 금액 부족, 칸 부족, 상대가 다른 Zone으로 이동 | 금화·아이템 이동 없음, 거래는 열린 채 동의 해제 | 9 |
| 거래 이탈·만료 | 세션 종료 취소, 취소 유실 뒤 만료 | 아이템·참여 해제, 만료된 거래는 다음 조작이 닫음 | 9 |
| 캐시 삭제 | Redis 전체 초기화 | 자산 유지, 조회 모델로 캐시 복구 | 7 |
| PG 중단 | 거래 중 DB 접근 차단 | 성공을 가장하지 않음, 결과 재조회 | 10 |
| 백업 복원 | 새 DB에 외부 백업 복원 | 자산·원장·미발행 이벤트 대사 | 10 |
